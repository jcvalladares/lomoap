Inheriting ManuScripts Inheriting ManuScripts Save Page to .PDF To reduce costly ManuScript re-work for similar requirements, Duck Creek Technologies has developed the Inheritance Model. With the Inheritance Model, you can reuse the content of any ManuScript and extend it in subsequent ManuScripts. When a ManuScript is inherited from a base, the resulting ManuScript is called derived . Benefits of Inheritance There are many benefits to using inheritance in the EXAMPLE Platform ® , but the primary benefit is reusability. You create a base ManuScript and then reuse it in subsequent ManuScripts, making only the necessary changes. This also means that when you change the base ManuScript, the changes are automatically updated in ManuScripts that have inherited the base, as long as the updated fields have not been modified in the derived ManuScript. Issues with Inheritance Although inheritance brings great benefits to the EXAMPLE Platform ® , there are still design considerations and maintenance issues to keep in mind. Any inherited items that have been overridden in the derived ManuScript are not changed when you update the base ManuScript. You must change these items manually. First identify the items that must be changed. Then demote any overridden items in the derived ManuScript to bring in the new base definitions. Finally, modify these items again in the local ManuScript to reflect the changes that were made to the derived ManuScript. When you override an item that is used in calculations in the base ManuScript, the change you make may cause the calculations in the derived ManuScript to function incorrectly or not at all. When you edit the base ManuScript and move or rename a field, fields in a derived ManuScript still search the original paths. If you override the renamed or moved item in the derived ManuScript, the override link is broken. The ManuScript validation process identifies these unlinked override items, but carefully consider renaming or moving items in a base ManuScript. XML for an Inherited ManuScript No inherited elements actually exist in the ManuScript XML of an inherited ManuScript. There is instead a pointer in the XML to the inherited ManuScript. For more information on inheritance, see Inheritance . Creating Inherited ManuScripts To create an inherited ManuScript: Click the New ManuScript button . You can also: On the File menu, click New . Click Inheritance Wizard . The ManuScript Catalog dialog box appears. Click the base ManuScript, and then click Load . The new ManuScript, derived from the base ManuScript, appears. Inheriting into an Existing ManuScript To inherit a ManuScript, the base ManuScript must be in the Catalog. The base ManuScript can be a linked ManuScript. To inherit into an existing ManuScript: Open the ManuScript to be derived from the base ManuScript. On the File menu, click ManuScript Properties . On the Inheritance tab, click the Ellipsis button to the right of Inherited ID . The ManuScript Catalog dialog box appears. Click the ManuScript to inherit. Click Load . In the ManuScript Properties dialog box, click OK . Any given ManuScript can inherit up to three other ManuScripts, one each for fields, pages, and forms. Changing a Derived ManuScript A ManuScript derived from a base ManuScript is not a finished product. It is only a starting point. You still need to make the changes specific to the particular ManuScript you are creating. In a derived ManuScript, you can change inherited groups and fields or add new ones. Inherited, changed, and new groups and fields are indicated visually. Field and group names are displayed: In italics when they are derived. In bold if they have been changed. As normal text when they are created in the current ManuScript. Demoting or Reverting Changes to Inherited Fields You can remove a change you make to a derived field by demoting it, or making it revert back, to the original form found in the inherited ManuScript. To demote or revert a field: Click a changed field. On the Edit menu, click Demote/Revert Field . The Confirm Demote/Revert dialog box appears. You can also: Right-click the field, and then click Demote/Revert Field . Click OK . The field name is no longer bold, signifying a changed field. It reverts back to italics, indicating that it is a derived field. Viewing a ManuScript Inheritance Chain You can view a ManuScript's inheritance chain in EXAMPLE Author ® in two ways: On the Inheritance tab of the ManuScript Properties dialog box ( File > Properties ). In the Inheritance dialog box ( View > Inheritance ). ManuScript Properties Dialog Box The Inheritance tab on the ManuScript Properties dialog box ( File > Properties ) allows users to view and define a ManuScript's inheritance chain. Depending upon the type of inheritance used by a ManuScript, the Inheritance tab may display that ManuScript's inheritance chain in two ways. The Inherited ID , Inherited Page ID , and Inherited Form ID fields specify the ManuScripts directly inherited by the derived ManuScript. If a ManuScript's inheritance chain is defined using these fields, that ManuScript only contains information about ManuScripts that are directly inherited. If those inherited ManuScripts are, in turn, derived from other ManuScripts, users must open the inherited ManuScripts to view their inherited ManuScripts. Users must continue opening each ManuScript specified on the Inheritance tab of derived ManuScripts until they reach the bottom of the inheritance chain. The Inheritance Maps section specifies the entire inheritance chain for the active ManuScript. If a ManuScript's inheritance chain is defined using this section, that ManuScript contains information about each ManuScript in its inheritance chain. As a result, users can view the entire chain for each type of inheritance (data, pages, and forms) in this section without opening any additional ManuScripts. Inheritance Dialog Box The Inheritance dialog box ( View > Inheritance ) allows users to view an entire ManuScript inheritance chain for each type of inheritance (data, pages, and forms) and, if desired, open any ManuScript in that chain.
