How Inheritance Works How Inheritance Works Save Page to .PDF To understand how inheritance works in the EXAMPLE Platform ® , users must understand several concepts, including the programming concept behind inheritance, key inheritance definitions, the general EXAMPLE ManuScript™ inheritance model, and the implementation of inheritance within the EXAMPLE Platform ® . The Inheritance Programming Concept The EXAMPLE Platform ® inheritance model incorporates a number of principles from the Object-Oriented Programming (OOP) technologies used in computer programming. A few important OOP definitions for words used in this document appear below. These definitions are generic in nature and reference classes or objects from a computer programming point of view. These principles apply, however, to ManuScript inheritance. Term Definition Inheritance Inheritance allows a class to extend or tailor behavior derived from a similar class to respond appropriately to specific needs. In object-oriented programming, inheritance provides a way to form new classes using pre-defined classes. These new classes use the attributes and characteristics of old classes, and then modify or extend those attributes to accommodate needs of the new class. Inheritance helps to effectively reuse existing code with a minimal number of changes. Base A base class is a class from which other classes are created or derived. Derived A derived class is a class derived from a previously defined base class. A derived class inherits all of the variables and methods of the base class from which it inherits. It may modify (or override) the behavior of any of those members or methods, and it may add new members or methods. A derived class may become the base class for another derived class. Override A derived class may replace the implementation of an aspect—typically a behavior or method—that it has inherited from its base with its own definition. When an item is redefined in this way, the item is said to have an override definition and will take on the characteristics of the new definition. Use The word use defines a relationship between two classes that are defined separately but contain objects that use (or call) methods from the other class. Two classes that use one another do not have to be based on the same class definition. Is The word is defines a relationship between a derived class and its base class. For example, when class B derives itself from class A, class B is a type of class A. Contains The contains relationship is a variation of the use relationship. A class may contain the class it uses. In this case, the creation of the referenced class is the responsibility of the calling class. EXAMPLE ManuScript™ Inheritance Definitions In addition to the previously mentioned OOP definitions, definitions of specific terms used for ManuScript inheritance can help facilitate understanding of ManuScript inheritance. The following terms are commonly used in relation to ManuScript inheritance. Term Definition Physical or Local Model Actual XML contained in the active ManuScript. This XML does not include XML from inherited ManuScripts. Logical or Assembled Model View of a derived ManuScript with all inheritance resolved and assembled. This XML image is the sum of all base ManuScripts used by the active ManuScript. For example, if B inherits A, and C inherits B, the logical model of C is the assembled view of all three ManuScripts A, B, and C. The system supports any number of inheritance layers. Local Definition Item in a ManuScript that originates in that ManuScript. A locally defined item originates and contains its definition in the active or current ManuScript. Base Definition Item in a logical model that is derived from one of the base ManuScripts and is not part of the physical model of the active ManuScript. Override Definition Item inherited from a base ManuScript that has been redefined (overridden) in the active (derived) ManuScript. An override definition is a local definition that replaces the base definition. Abstract Item Inherited item in a ManuScript that exists in the logical model only to preserve the ManuScript hierarchy. Abstract items do not override base definitions. Delete Delete an item from the base ManuScript. Demote or Revert Demote an overridden item or revert it back to its original base behavior rather than deleting it. Supersede Override entire sections of a ManuScript. This replaces base-defined fields and groups, PageSets, or forms with fields and groups, PageSets, or forms from an entirely different base ManuScript. ManuScript Inheritance Model Overview Based on OOP definitions, ManuScript inheritance can be described as allowing any ManuScript to be the base class from which a new ManuScript is derived. Any named item in the base ManuScript can have an override definition in the derived ManuScript that establishes new behaviors while inheriting all the rules and behaviors of all other items in the base ManuScript. ManuScript A can be considered a traditional ManuScript, where all information needed to operate is contained in the ManuScript itself. The actual XML stored for the ManuScript contains all the information needed for this ManuScript. This means the physical model, or the actual XML, contains all information seen and used in the ManuScript. Because it is derived from ManuScript A, ManuScript B need only keep track of the changes and additions to the base (ManuScript A). The actual XML stored for the derived ManuScript need only be those items with modifications. The logical view of ManuScript B, however, includes all the base definitions (from both ManuScripts) and the override definitions (in ManuScript B). The physical view defines how ManuScript B looks locally, containing only the changes made from the base ManuScript (ManuScript A). Implementation of EXAMPLE ManuScript™ Inheritance EXAMPLE ManuScripts™ indicate inheritance by an attribute on the <properties> tag at the beginning of the ManuScript XML. When a ManuScript is inherited, the inherited attribute exists and contains the ManuScriptID of the base ManuScript. This attribute is the only indicator needed to move a ManuScript into the inheritance model. <ManuScript>
  <properties manuscriptID="uniqueID" inherited="baseManuScriptID" … A ManuScript may inherit from a ManuScript that in turn inherits from another ManuScript. The EXAMPLE Platform ® supports any number of parent and child inheritance layers. Each ManuScript, however, may directly inherit from only three base ManuScripts: one for field, group, and table data; one for pages data; and one for forms data. By default, EXAMPLE Author ® displays the logical model of a ManuScript. You can change this setting to use the physical model, however, by specifying to do so in the parameters of an EXAMPLE Author ® request. EXAMPLE Server ® executes a derived ManuScript differently than it executes a traditional ManuScript. The runtime methods of the EXAMPLE Server ® (such as the <ManuScript.getValueRq> for rating and rules and the <ManuScript.getPageRq> for interview processes) operate differently between derived and traditional ManuScripts. When a user initiates an execution method for a derived ManuScript, the engine uses the logical image of the ManuScript as the runtime image when it initializes itself for runtime operations. The EXAMPLE Server ® compiles this ManuScript XML when the first request for the ManuScript is processed. This process creates the runtime instance of the assembled ManuScript rules as defined by the logical image of the ManuScript. For an inherited ManuScript to operate correctly, referenced base ManuScripts must exist on the same EXAMPLE Server ® as the derived ManuScript. Thus, because inheritance may extend through any number of layers, all the ManuScripts in a given inheritance chain must exist on a given EXAMPLE Server ® for the derived ManuScript to operate correctly. Granularity of Inheritance Levels of inheritance granularity define the points at which ManuScript overrides occur. Once an item is overridden, the override definition is responsible for the full implementation of that item. This means that when a field is overridden, all details of that field are copied into the derived ManuScript, and only the override modifications apply. That is, the modified definition replaces the inherited base definition.
