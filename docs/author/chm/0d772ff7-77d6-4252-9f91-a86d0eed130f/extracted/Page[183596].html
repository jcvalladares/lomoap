Inheritance and EXAMPLE Server®

Save Page to .PDF

The following sections describe how EXAMPLE Server® facilitates ManuScript inheritance.

Deployment

Deployment sends the physical image of all ManuScripts needed by a given ManuScript to the target EXAMPLE Server®. The deployment process includes all ManuScripts upon which the active ManuScript is dependent.

Runtime Loading of Logical Model

When the runtime version of a ManuScript is needed, the logical view of the ManuScript is assembled on the first demand for the ManuScript. As a result, all ManuScripts upon which the active ManuScript is dependent must exist on the EXAMPLE Server®.

Development Platform Modifications

When working on a development EXAMPLE Server® used by multiple developers, users need to ensure that runtime images loaded for rating and testing are correct each time a runtime request is initiated. Because the EXAMPLE Server® maintains a cache of the ManuScripts in memory, runtime components built from the logical image in memory may be stale. Changes recently made to the base ManuScripts may not appear in the cached logical image.

To accommodate this problem, you can configure an EXAMPLE Server® to be a development server. This configuration forces the runtime image of a ManuScript to refresh each time a user initiates a request. This development configuration, however, comes with a performance cost and should be reserved for development servers only.
