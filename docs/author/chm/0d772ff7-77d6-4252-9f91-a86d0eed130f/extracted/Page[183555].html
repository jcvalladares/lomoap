Working with CSS Override Styles

Save Page to .PDF

You can assign CSS override styles to individual page elements using the CSS Selector in Page Designer.

To open the CSS selector:

  • To the right of the appropriate Style property for the appropriate element, click the CSS button .

Applying Override Styles

To apply an override style to a page element in Page Designer:

  1. To the right of the appropriate Style property for the appropriate element, click the CSS button .

    The CSS Selector dialog box appears.

  2. In the Available Styles list, click a style to apply, and then click Add. (You can multi-select using CTRL+click.)

    The Available Styles list in the CSS Selector displays only those styles defined with a class-only selector. It will not display styles with selectors containing conditions or other content. If you wish to define styles with more complex selectors, you can do so in the x_interview.css override file in the [GlobalRootPath]\Express\Skins\[SkinName]\css directory. To cause these styles to appear in the CSS Selector, you must first define the style with a class-only selector. (The style may contain declarations or be empty.) You can then create additional styles with the same class name and the desired selectors. The class-only style will appear in the Available Styles list, and selecting that style will then apply all styles with that class name. However, the Definition box will only display the declarations defined for the class-only style.

    The selected styles appear in the Styles to Apply list, and the definition for all styles in the list appears in the Definition box.

  3. (Optional) To move a style up or down in the hierarchy, click the style, and then click Move Up or Move Down .
  4. Click OK.

Removing Override Styles

To remove an override style from a page element:

  1. To the right of the appropriate Style property for the appropriate element, click the CSS button .

    The CSS Selector dialog box appears.

  2. In the Styles to Apply list, click the style, and then click Remove.
  3. Click OK.

Viewing Override Style Definition

You can view the definition for the override styles applied to certain page elements in the CSS Selector dialog box.

To view definition for the override styles currently applied:

  1. To the right of the appropriate Style property for the appropriate element, click the CSS button .

    The Definition box beneath the Styles to Apply list contains the total definition for the selected styles.

  2. (Optional) Click styles in the Styles to Apply list to isolate the definition for each specific style.

    Definition for items selected in the Styles to Apply list appears in italics. The Definition text box is read-only.

Managing Override Styles

You can add, delete, or modify the available override styles using the CSS Manager tool in EXAMPLE Author®. This tool reads from and writes to the x_interview.css override file in the Global Root Directory\Express\Skins\CustomSkin\css directory. From the CSS Manager, you can access and edit the x_interview.css override file.

To open the CSS Manager:

  • In EXAMPLE Author®, on the Tools menu, click CSS Manager.
Adding a New Style

To add a new style in CSS Manager:

  1. On the Tools menu, click CSS Manager.

    The CSS Manager dialog box appears.

  2. Click Create New.

    The Create New dialog box appears.

  3. Enter the Class Name for the style, and then click OK.

    The new style appears in the Style drop-down list.

  4. In the Definition pane, define the style by performing one of the following actions:
    • Click a property from the list of properties, and then click Insert.

      You can also:
      Double-click the desired attribute.

      Define the property in the text box.

    • Enter the desired definition in the text box.
  5. When finished, click Apply to save the definition and continue working in CSS Manager, or click OK to save the definition and close CSS Manager.

Deleting a Style

Before deleting a style in CSS Manager, verify the style is not used in any ManuScripts using the x_interview.css file.

To delete a style in CSS Manager:

  1. On the Tools menu, click CSS Manager.

    The CSS Manager dialog box appears.

  2. In the Style list, click the style you wish to delete.
  3. Click Delete.

    A confirmation dialog box appears.

  4. In the confirmation dialog, click Yes.

Modifying a Style

To modify a style in CSS Manager:

  1. On the Tools menu, click CSS Manager.

    The CSS Manager dialog box appears.

  2. In the Style list, click the style you wish to modify.
  3. In the Definition pane, modify the style as desired.
  4. When finished, click Apply to save the definition and continue working in CSS Manager, or click OK to save the definition and close CSS Manager.

Specificity

The EXAMPLE Platform® uses specificity to determine the order in which identical CSS selectors are applied. For example, if .myClass {float:left; } and .myClass {float:right; } CSS selectors existed (in that order), the .myClass elements would float right because the value of the last CSS selector in the list takes precedence when the CSS selector values are the same.

CSS elements within a <div> element take precedence because they are considered to be more specific than elements not contained in a <div> element.

Calculating Specificity Values

To determine the specificity of nested CSS selectors, each selector is assigned a point value.

The following table includes a breakdown of the points assigned to each type of selector:

CSS Selector Type Value
id selectors (for example, #myId) 100
class selectors (for example, .myClass) 10
HTML selectors (for example, div) 1

For each selector in a group, the point values are added together. The result is the specificity value.

The following table includes some examples of how specificity values are calculated.

Groups of Selectors Specificity Value
.acrossFieldGroup>div 11 (10 + 1)
.acrossFieldGroup>.acrossBeforeFormLabel 20 (10 + 10)
#requiredAsterisk 100
.required #requiredAsterisk 110 (10 + 100)

Overriding Specificity

Some CSS files (for example, forms.css) use the greater than (>) symbol to combine CSS selectors into groups to reduce the number of inconsistencies possible in dynamic layouts. As a result, some .css file definitions have become more specific than most of the selectors in the x_interview.css file and could cause issues to surface.

Determining Whether Specificity has Been Overridden

To determine whether specificity has been overridden:

  • Using the developer toolbar in Internet Explorer 8, the Firebug feature in Mozilla Firefox, or the inspector feature in Google Chrome, search for overridden CSS styles in the toolbar. Overridden CSS styles appear with a line through them.
Overriding Specificity

When experiencing specificity issues, you can often work around them by overriding specificity rules using the "!important" rule.

To override specificity rules:

  • Add the !important rule to the end of the CSS selector to which you wish to give precedence. The following is an example of a CSS selector with overridden specificity. 
    .x_FloatRight { float:right !important; }
