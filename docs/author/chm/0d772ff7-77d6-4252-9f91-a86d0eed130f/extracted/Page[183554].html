Actions

Save Page to .PDF

Actions are buttons that can be placed in a group, section, table, or grid widget. You can add or remove actions, or define properties for actions.

Adding an Action

Page Designer View

To add an action:

  1. Click the appropriate section, table, or grid widget.
  2. On the Edit menu, click Insert action.

    You can also:
    Right-click a section, table, or grid widget, and then click Insert action.

  3. Define the properties for the action.

Deleting an Action

Page Designer View

To delete an action:

  1. Select the action you wish to delete.
  2. Click the Delete button .
  3. In the Confirm dialog box, click Yes to confirm the deletion, or No to cancel.

Defining Actions

Page Designer View

To define an action, you specify the following properties.

Properties vary by action.

Property

Description

General

Action Type

Action to be performed. Options vary depending upon what the action is added to:

  • Delete Record (sections/tables/grid widgets)
  • Duplicate Record (sections/tables/grid widgets)
  • Add Record (groups)
  • Goto Page
  • Calculate (discard results)
  • Calculate (keep results)
  • Detail for this Record (sections/tables/grid widgets)
  • Iteration Links (groups)
  • Custom Action
  • Mark-for-Delete (sections/tables/grid widgets)

Caption

Button text to describe the action.

Show Condition

Conditional field that specifies when to show the action.

Pre-Action

Field to be executed before this action is performed.

Post-Action

Field to be executed after this action is performed.
Use Editing ID Boolean indication of whether or not to use the value of the ManuScriptEditingID field for the ManuScript, PageSet and Page to be loaded. If false or if the ManuScriptEditingID field has no value, the system will use the ManuScript, PageSet, and Page specified by the ManuScript ID, Page Set, and Page properties.

Page

Page to be loaded when the action is Goto Page.

Page Set

PageSet that contains the page to be loaded when the action is Goto Page.

ManuScript ID

ID of ManuScript. If empty, the system uses the current ManuScript.

Field (Optional)

Field to use as an entry point for the calculation instead of the Primary Value. Only available with the Calculate (discard results) and Calculate (keep results) actions.

Express Action

Built-in action to be passed to the EXAMPLE Express® system. Each EXAMPLE Express® Action is related to a post Action and optional target Page for the action. The post Action defines the actual command to be performed by Express, such as save, submit, or loadHistory. The target Page identifies the page name to which EXAMPLE Express® should navigate, such as print, open, or new. The format is postAction:targetPage using a colon to separate the post Action and the target Page.
 

Duck Creek Technologies, Inc. does not support the use of a custom request with an Express Action. If you need to run a request before the Express Action is executed, use a PreEvent instead.

Advanced

PopUp

Indication of whether the page opened by the action should appear in a pop-up window, or whether to close an open pop-up window.If this property is defined, the following additional properties appear:

  • PopUp Title — (optional) Title caption for the pop-up window.
  • PopUp Width — Specification of width (in pixels) of the pop-up window.
  • PopUp Height — Specification of height (in pixels) of the pop-up window.
  • Popup Class — Specification of the CSS class to be applied to a popup for enhanced control of individual popup windows. The specified class is applied with the .x-window class.
  • Hide Popup Close Button — Indicates whether to hide a popup's close button and force the user to interact with the popup before continuing.

Show Processing Message

Specification of a "processing" message to display for actions that take additional time to process.

Any action taking longer than four seconds (or a number specified in EXAMPLE Express® skins) will automatically display a loading message after four seconds.

Confirm

Indication of whether to require the user to confirm the action before processing the action. If this property is defined, the Confirm Text property also appears.

PreEvent Field

Specification of validation rules that must be performed before executing the action. When the specified field returns a blank value or a space, the action can be performed. When the specified field returns any other value, the value is displayed to the user and the action is not performed.

If this property is defined, the following additional properties appear:

  • PreEvent Context — If the PreEvent Field is part of an iterative group, indicates the context for the iterative group.
  • PreEvent Confirm — Indication of whether to require the user to confirm the action before processing the action.
  • PreEvent Confirm Text — Specification of the text to appear in the confirmation message.
  • PreEvent Field Alert Only — Transforms the confirmation message to an alert message. Use the PreEvent Confirm Text property to specify text for the alert message.

Ignore Validation

Indication of whether to skip field-level validation before leaving a page.

Cancel Changes

Indication of whether to remove any changes not stored in the session when the action is selected.

Print Action

Specification of a print job to print. This property requires the following syntax: printJob:[print job name]|[ManuScript ID]. (ManuScript ID is optional.)

In addition, you can add three custom parameters to this property:

  • effectiveDate
  • quoteIDs
  • portfolioIDs
Suppress Refresh

Indication of whether the page should refresh after the user views a rating worksheet. Options include:

  • True – Prevents the refresh from occurring.
  • False – Allows the refresh to occur.

This property is only available when a value has been entered for the Print Action property.

Custom Command

Specification of a custom command. Currently, the following commands are valid:

  • windowClose — Performs a window.close() JavaScript function.

Print Job

Identification of the print job to use to build the forms list. This property is valid only when one of the following Express Actions has been defined:

  • initPrintJob
  • initAsyncPrintJob
  • runRulesPrintJob
  • runRulesAsyncPrintJob
  • closePrintJob
  • previewPrintJob
  • previewAsyncPrintJob

Print Job ManuScript

Identification of the ManuScript containing the print job to use to build the forms list. If blank, this property defaults to the current ManuScript. This property is valid only when one of the following Express Actions has been defined:

  • initPrintJob
  • initAsyncPrintJob
  • runRulesPrintJob
  • runRulesAsyncPrintJob
  • closePrintJob
  • previewPrintJob
  • previewAsyncPrintJob

Setting the Action Type Property

Page Designer View

You can define the following types of actions.

Action

Description

Delete Record (sections/tables/grid widgets)

Deletes an iteration of an object from the session data document. The default behavior returns to the current page after the object is deleted. If you specify a page or PageSet, EXAMPLE Server® deletes the object and then goes to the new page.

Duplicate Record (sections/tables/grid widgets)

Duplicates an iteration of an object in the session data document. The default behavior returns to the current page after the object is duplicated. If you specify a page or PageSet, EXAMPLE Server® duplicates the object and then goes to the new page.

Add Record (groups)

Adds an iteration of an object to the session data document. The default behavior returns to the current page after a new object is added. If you specify a page or PageSet, EXAMPLE Server® adds the object and goes to the new page that contains only the iteration of the newly added object.

Goto Page

Routes the interview to a different destination. Under normal circumstances the Goto Page destination is determined when the page is rendered. However, it is possible to determine the Goto Page destination after the button is pressed.

To determine the destination page after the button is clicked:

  • Enter the name of a field containing the name of the destination page, prefixed by a $ (dollar sign). When the <ManuScript.getPageRq> request is processed and the value of the Goto Page command begins with a $, the specified field is executed to determine the name of the page or PageSet to which to route.

Calculate (discard results)

Calculates the ManuScript and do not preserve the calculated results in the session data document.

Calculate (keep results)

Calculates the ManuScript and preserve the calculated results in the session data document.

Detail for this Record (sections/tables/grid widgets)

Displays fields for a single iteration. If you specify a page or PageSet, the detail displays on the specified page. (The root group for a page displaying a single iteration must be the iterating group.)

This action cannot be used to retrieve data stored in named documents.

Iteration Links (groups)

Returns a set of actions in conjunction with iterating objects. The number of actions depends on the current number of repeating objects in the data document for the context of this group and the values in the following Iterations fields:

  • Maximum — Each action displays only the number of objects entered in the Maximum field for the specified PageSet.
  • Links — The value in the Links fields specifies the maximum number of actions returned on a page.

Custom Action

Executes a <getPageRq> request that contains an attribute of command="custom". This indicates to the application that custom processing must occur. The setting of command="custom" is ignored by EXAMPLE Server®.

Mark-for-Delete (sections/tables/grid widgets)

Deletes an iteration of an object in the session data document.

To set the value of the Action Type property:

  1. Click the action.
  2. On the Definition tab, click Action Type.
  3. In the Action Type list, click the appropriate option.

    The action type is added to the selected action in the Page Designer list.

Setting the Page Property

Page Designer View

The Page property specifies the page to be loaded when the action is Goto Page. This value can be determined at two different times:

  • When the page containing the action is rendered
  • When the action is clicked

By default, the value of this property is determined when the page containing the action is rendered. To determine the value of the property when the action is clicked, you must specify the field to execute when the action is clicked, prepending the field name with a dollar sign ($) and surrounding the entire expression with quotations marks (e.g., "$FieldName").

To set the value of the Page property:

  1. Click the action.
  2. On the Definition tab, click Page.
  3. Specify a value, or, to the right of the Page text box, click the Ellipsis button  to use the Reference Select dialog box to select a field. If the system should determine the value of the property when the action is clicked, prepend the field name with a dollar sign ($) and add quotation marks around the entire expression (e.g., "$FieldName").

Setting the PopUp Property

Page Designer View

The PopUp property specifies whether the page opened by the action should appear in a pop-up window, or whether to close an open pop-up window. If this property is defined, the PopUp Title, PopUp Width, and PopUp Height properties appear. (These properties are only applicable if the PopUp property equals 1.) Setting the Button Quick Tip Property

Page Designer View

The Button Quick Tip property indicates whether a tooltip should appear when the user hovers over a specific button.

To set the value of the Button Quick Tip property:

  1. Click the action.
  2. On the Definition tab, click Quick Tip.
  3. Specify a value, or, to the right of the Quick Tip text box, click the Ellipsis button  to use the Reference Select dialog box to select a field.
