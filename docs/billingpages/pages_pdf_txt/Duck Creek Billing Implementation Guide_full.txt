Duck Creek Billing™ Implementation Guide
The Duck Creek Billing™ Implementation Guide takes the billing user from installation to a customer implementation
ready for the hands-on billing user. The guide is organized by feature, and includes the appropriate configuration,
customization, and integration work needed to use each feature.
For more information about using billing, see the Duck Creek Billing™ User Guide . For more information about the
features included in billing, see the Duck Creek Billing ™Features Overview .
Duck Creek Billing™ Installation
Duck Creek Billing™ requires installation of the following EXAMPLE Platform ®products:
•EXAMPLE Server ®must be installed first
•EXAMPLE TransACT ®
•EXAMPLE Asynchronous Request Viewer
•EXAMPLE Forms™
Installation of EXAMPLE Express ®is also recommended, and is required for the installation of the Billing On
Demand Components. Without EXAMPLE Express ®, Duck Creek Billing™ pages will not be viewable out of
the box.
System requirements for Duck Creek Billing™ are:
•Microsoft Internet Explorer 8 or higher
•Microsoft Message Queuing
•Internet Information Service (IIS) v.7
When installing IIS for the first time, the uninstall .NET Framework must be uninstalled first. After
successfully installing IIS, reload .NET Framework
•Microsoft .NET Framework v3.5 (SP 1)
•Microsoft SQL Server 2005 (SP 3) with Full Text Search (FTS) and Reporting Services enabled.
New SQL Server 2005 users should install FTS when installing Microsoft SQL Server 2005. Users who
are upgrading should check in Control Panel>Administrative Tools>Services to see if FTS is installed
and is started. If it is not shown in the Services folder, install it from the SQL 2005 CD.
The following services must be started to run Duck Creek Billing™:
◦DuckCreek_MSMQBillingListener_EXAMPLE SERVER
◦DuckCreek_Async_Request_Queue_EXAMPLE Async Queue O
◦DuckCreek Scheduled Requests EXAMPLE Billing Components O
•Microsoft Excel 2003 for generating Excel format agent commission statements (EXAMPLE Platform ®4.2.2. or
later)

Compatible versions of Microsoft Excel and SQL Server are required. SQL Server 2005 requires
Microsoft Excel 2003.

instructions in Modifying or Repairing an Installation .

◦Click I accept the terms of the license agreement to accept all terms of the agreement.

process.

appropriate scripts. (You can view a list of differences between the existing structure and these scripts by clicking the
Preview Changes button.) If the Database Setup check box is selected, the installation then makes the appropriate
changes to the existing database tables and columns.

appropriate item.

The User Interface
Duck Creek Billing™ is for real-world people performing real-world tasks. The intuitive user interface offers quick,
functional access to the information and processes that users access most frequently. Key elements of the user
interface include:
•The Billing Dashboard
•The Account Home page
•The Policy Term Summary page
•Controls (grids, dates, and validation)
Duck Creek Billing is a highly customizable and configurable product. Not all pages may appear as described
in this user guide, which is based on out-of-the-box settings.

The Billing Dashboard
From the Billing Dashboard page, a user can:
•Search for a payment.
•Enter a single payment from the Cash Management screen instead of within an account.
•View summary information for payments automatically or manually entered that were not posted to a policy or
account.
•Create an account in the billing system without going through policy issuance.
•View a list of recently created or accessed accounts.
•Open an available report with one click.
•View notifications and tasks.

Working with Controls
The Duck Creek Billing™ user interface incorporates ExtJs2.2, making available a diverse set of GUI-based form
controls (widgets) including:
•Grids and filters
•Date fields
•Validation functions
Grids and Filters
In Duck Creek Billing™, users can change the items displayed in a grid using filters or special options on the grid.
Items that are displayed in a list may be determined by using the Support_CodeListExclusion database table. If the
user selects an item from the grid that is not displayed, that selection will override the exclusions, and the item will
appear on the page. See Working with Grids and Filters in the Duck Creek Billing™ User Guide .
Grids in Duck Creek Billing™ integrate a wide variety of tools that allow users to easily view customized information.
These grid types include:
•Grid Types
◦Grouping grids – Group items within the grid. Common rows are grouped together based on the grid's
configuration.
◦Preview grids – Display an extra information row per item. This information row can be collapsed or
expanded (for a single row or for all rows) using a button in the grid toolbar.
•Check box grid – Display a check box on each row, based on a row rule check. These grids can store all
selected rows in a paging grid, storing the items selected on each page until the user is ready to submit the
selections.
•Grid toolbar – Allow users to display or hide items according to their preferences.
•Column filtering – Allows users to filter grid data within each column. Data is displayed based on all filters the
user has selected. Filtering types include:
◦Dates – Allows less than or equal to ,greater than or equal to , and equal filtering.
◦Text – Allows text searches.
◦Amounts – Allows less than or equal to ,greater than or equal to , and equal filtering.
◦Support table values – Loads selectable items using check boxes.
13 Contains proprietary information. Copyright 2012 Accenture Duck Creek. All rights reserved.

•Row classification – Allows a class name to be appended to a row to change styling. This classification is based
on a rule provided through a JavaScript function.
•DataOnLoad event – Allows the onload event to occur immediately after a page or image is loaded.
Date Fields
Duck Creek Billing™ offers the following date field functionality for date fields:
•System pages with their own Ext Js date fields that do not interfere with interview pages.
•Available events for date fields:
◦onBlur event
◦onChange event
◦onKeyUp event
◦onKeyPress event
Date fields are turned on by providing a function that is called for one of the listed events. The
function is passed as a configuration parameter in the XSL. If the screen XSL does not pass a
function, the event is not processed.
Validation Functions
•Credit Card Validation –The credit card validation function performs a behind-the-scenes validation on all
entered credit card numbers. All standard credit card types are handled.
•Time Validation –The Time Validation function checks that any entered time is valid.

Out of the box, Duck Creek Billing™ does not allow users to change the selected bill plans at the account or policy

To change bill plans during policy re-issuance or renewal:

Re-issue pages.
1.Verify that the Submission page displays the current bill plan for the policy being re-issued or renewed.
2.Verify that the options displayed in the Select Billing Plan list are compatible with the selected account level bill
plan.
3.Open the NewPolicyTermCommon.xsl file in Notepad or another text editor program.

Working with the Agency Lite Feature
Direct bill systems typically use a gross premium basis for statement reconciliation. The Agency Lite feature in Duck
Creek Billing™ allows agencies with low volumes of small agent accounts to reconcile statements on a net settlement
of accounts basis using direct bill features.
37 Contains proprietary information. Copyright 2012 Accenture Duck Creek. All rights reserved.

Because manual reconciliation is required for each statement and for the creation of commission records,
agency lite accounts are not recommended for large numbers of agents or for agents with more than 50
policies per statement.
Important considerations for agency lite accounts include:
•Net payments indicate that the agent is retaining the commission.
•Gross payments indicate that the commission should be paid to the agent.
•Manual data entry is not required if the statement is paid in full.
•Once an account setting is specified as gross or net, it cannot be changed.
•Net and gross commission payments cannot be mixed within an account.
Commission authorization records in direct bill are usually written to the CommissionAuthorization database table
based on rules in the commission scheme specified in the Policy Plan Setup Options. For agency lite accounts, no
commission scheme is specified, so no commission records are written.
The balances in direct bill always represent gross amounts. If payment is made in the net amount, an open balance
representing the commission the agent has retained will remain.
Configuring Agency Lite Accounts
To configure the Agency Lite option:
1.In the Billing Account Options settings in the Account Type section, make the following selections:
◦In the Account Type Code list, click Agency Lite .
◦In the Gross/Net Indicator list, click the appropriate commission option.
2.Click Save Changes .
3.In the Policy Plan Settings , in the Follow Up section, clear the PCNAllow check box to prevent the Agency Lite
policies from going into PCN status.
4.Click Save Changes .
5.Open the appropriate ManuScript.
6.In the Commission_PolicyPlan.Scheme field in the policy plan ManuScript, clear the default value to prevent
commission authorization records from being written.
For information about entering payments for an Agency Lite account or for writing off commission adjustments, see

Working with Monthly Reporting
Monthly Premium Reporting allows a business to pay higher premiums during the time the business is more active,
and lower premiums during times of reduced activity. Pricing for an MPR policy is based on the annual estimated
exposure or payroll subject to the rates, the exposure modification, and other factors the carrier has in the filing. By
reporting the actual exposure, the premium due can be accurately calculated. Businesses that may benefit from MPR
include construction contractors, amusement parks, and ski resorts.

Manually Redistributing Installments
Manual installment redistribution allows customers to have additional time to pay a large amount due, such as final
audit premiums. When configured, this feature is accessible from the Installment Schedule page as a link in the
Balance column. The link is only available when the Installment Schedule view is expanded, an open balance exists,
and the Account Type Code does not equal Agent .
Installments can be manually redistributed outside the current policy term dates, and any items that have been
redistributed outside the policy term are catch-up items on the next installment.
To have the required permissions to manually redistribute an installment, the logged in user must be
assigned the role of BillingAgent with the BIL_ManualInstallmentRedistribution privilege. This is an out-of-the-
box privilege assigned to the BillingAgent role. For more information on billing roles and privileges, see
Creating a Billing Role in the Duck Creek Billing™ User Guide .
Creating a New EXAMPLE Server ®Request
The <BillSchedule.redistributeInstallmentBalanceRq> request must be created to control the redistribution. This
request must specify the BillItemScheduleID , the earliest installment date for the redistribution, and the number of new
installments to create.
Redistributed installments will have a different installment type code than regular installments so they can be easily
identified in the database tables. This change also allows credit allocation to work correctly since the usual method of
matching debits based on effective and expiration dates will not work with redistributed installments.
The existing credit allocation processing will be changed to search for debits that could be outside the range of
installment dates based on their effective and expiration dates.
Working with a Late Entered Policy
Through ManuScript configuration, the Late Entered Strategy feature allows a Duck Creek Billing™ user to insert an
out-of-cycle draw for an EFT invoice account for a late entered new business policy. Out of the box, without the Late
Entered Strategy feature enabled, when the scheduled invoice day has already been passed in the current month, a
late entered new business policy installment is added to the next scheduled installment for the account, resulting in as
much as 31 days of coverage without premium payment.
TheLate Entered Strategy feature has a positive effect on cash flow and commission authorization, in addition to
protecting policy equity by minimizing the amount of time coverage is provided without payment.
TheLate Entered Strategy is valid for a new business premium by EFT invoice only. Other transactions, such
as endorsements and renewals, are scheduled based on the Late Entered Strategy Code value on the policy
plan associated with the policy. For more information, see Selecting Policy Plan Options .

Commission Plans
Before premium is issued, an overall commission rate or amount must be specified. The commission can be a
percentage or a flat amount, and it can vary by policy term or be the same across all policy terms. The commission
plan can vary by the following policy attributes:
•Agent Reference
•Line Of Business
•Master Company
•Issue System
•Product Code
•Inception Date
•Policy Term Effective Date
•State
Five customer-definable keys are also used to determine the correct commission plan. One of the keys can be used to
indicate the selected coverage and premium class combination. The same definable key can be used for a separate
line of business or product in more than one commission plan.
When a policy is rated, the commission rate or flat amount is determined by performing a look-up based on policy
attributes specified in the creation of the commission plan, including the customer definable keys. The search begins at
the lowest level of the hierarchy to obtain the correct commission plan, as well as the overall rate of commission or flat
amount.
Commission plan changes are supported through the use of effective and expiration dates, which allows new policies
to use new commission rates or flat amounts and commission distributions while existing policies use prior commission
rates or flat amounts and distributions.
The commission distribution specifies the entity type that will receive the commission distribution and the amount of the
distribution. Using the entity tiers created in EXAMPLE UserAdmin™, commission plans can be inherited from a higher
agent tier to a lower tier. A commission plan that is inherited from a higher tier can only be changed at the tier where
the commission plan was created.

Configuring Commission Options
Commission rate and eligibility are determined in the policy system and transmitted to Duck Creek Billing™ on the
policy term premium record. Records are written to database tables based on the commission scheme specified in the
Policy Plan Setup option. The CommissionStatementSchedule database table maps an agent to the statement
schedule and produces statements based on the data in the table.
The <BillCommission.buildCommissionStatementRq> request populates the following two tables:
•DC_BIL_DirectBillCommissionStatementSummary — Contains information needed by a check-writing
interface.
•DC_BIL_DirectBillCommissionStatementDetails — Contains details for statement make-up to generate
printable statement.
Most data in these tables is stored in an XML column.
Commission statement requests should be initiated serially from a single source and processed by a single
server to avoid possible race conditions between multiple threads and/or servers when writing to the
disbursements file.
Commission processing uses two requests:
•The <BillCommission.buildCommissionStatementRq> request uses the agencyId, statementDate, and
printDirectory attributes.
•The <BillCommission.printCommissionStatementRq> request uses the statementId and printDirectory parameters
to generate printable statements. This request initiates a report using SQL Server 2005 Reporting Services to
produce statements.
Reports are output as PDF files to the directory specified in the printDirectory attribute. If the print directory is not
passed in as an attribute, the DirectBillCommissionStatementsFolderRootPath setting in the Server.Config file is used.
The statement file name will be DirectBillCommissionStatement_Agency_[Agency]_[StatementDate]_[StatementId].pdf.
Customers are responsible for printing and sending the statements, or maintaining the files.

Working with Multi-level Commisisons
The multi-level commission feature is enabled by using the role-based security features in EXAMPLE UserAdmin™.
Recommended Reading:
TheEXAMPLE UserAdmin™ Overview describes the basic concepts of role-based security and how the
EXAMPLE Platform ®uses EXAMPLE UserAdmin™, and the "Initial Setup" in the EXAMPLE UserAdmin™
User Guide , which describes the process of working with entities, roles, and users.
EXAMPLE UserAdmin™ may be used to set up and define the entities, roles, users and hierachy (parent/child
relationships for commission distribution and plan inheritance. Commissions may be distributed at one or multiple
levels in the hierarchy as specified in the commission plan that is created for an account. Commission plans can be
created at one tier, and then be inherited by a lower tier, but they cannot be created at a lower tier and then be
inherited at a higher tier.
A policy's commission plan is determined when the policy is entered. The policy administration system retrieves the
commission plan ID and sends it to Duck Creek Billing™ where it is stored in each BillItem record. When the
commission is distributed, it pulls the appropriate commission plan using the commission plan ID. The necessary keys
are used to search from the lowest tier of the hierarchy to obtain the correct commission plan and distribution. The
commission distribution includes each recipient ID, as well as the recipients’ distributed commission percentage.
When a search for a commission plan begins, it is based on both the fixed and variable policy attributes specified in the
commission plan. The search begins at the lowest level of the hierarchy and moves upward. If no match is found at the
first level, the search moves to the next tier in the hierarchy. If a match is found at this tier, the commission plan is
returned. The search process continues through all the tiers, and if no match is found at the highest tier, an error is
returned.
For a given commission plan, the user may also specify different rates and distributions for new business and
renewals.

Requesting an Ad Hoc Statement
Commission statements are produced on a specified scheduled, usually monthly. Commission statement periods do
not have overlapping days. For example, the dates included in the commission begin with January 1, 2011, at 12:00
a.m. and ends with January 31, 2011 at 11:59 p.m.
The statement period for an ad hoc statement is specified by when the statement is generated. Ad hoc statements
include all the activity that has occured since the previous statement was produced. After an ad hoc commission
statement is produced, the next commission statement is produced according to the original schedule.
An ad hoc statement does not appear for viewing, but is produced in the format or formats specified in the commission
plan setup, and is automatically placed in the appropriate statement folder. An Archive folder is also created and
contains a copy of each statement format generated for an account. By default, this folder location is: C:\Program
Files\Duck Creek Technologies\DirectBillCommissionStatements .
To request an ad hoc statement:
•On the Commission Statement Maintenance page, click Request Ad Hoc Statement .
The statement is automatically placed in the archive folder and all other appropriate folders, based on statement
format.

Working with Automatic Letter Generation
When implemented, the Automatic Letter Generation feature allows users to integrate a third-party forms provider to
manage letters that are generated automatically.
Out of the box, generated letters (in the form of XML) are placed in the following directory: C:\Program Files\Duck
Creek Technologies\External Documents.
The appropriate letter is generated automatically when one of the following events occur:
•Billing_PostPaymentReversalEvent
•Billing_EFT_RepresentEvent
•Billing_ReversePaymentEvent
•Billing_EFT_RejectEvent
•Billing_PostDisbursementEvent
•Billing_EFT_ChangeEvent
Each event triggers a specific ManuScript which automatically generates the appropriate letter for the event. The form
data is generated as XML, and can be sent to a third-party forms provider. The conditions that trigger the events can
be configured or specified to provide additional flexibility. For example, the system could automatically create an EFT
payment rejection letter the same day the payment is reversed in the billing system. This provides the benefit of prompt
notification to the payor regarding the status of their payment, and provides information regarding the action required to
prevent cancellation of the associated policy or policies.
Other letters that could be automatically generated include notification of:
•Representment of an EFT payment following an initial rejection.
•EFT or other payment type rejection.
•Disbursement from the account.
•Changes to the EFT information held for the account.
When a letter is automatically generated for an account, the Recent Account Activity list is updated to include the
form name, the name of the third-party provider, a date and time stamp, a success or failure message, and link that
opens the letter for viewing.
The DCT_DocumentInterface section in the Server.config file contains the parameters used by the component map
and must be customized for each carrier's needs.

Troubleshooting Scheduled Activities
Duck Creek Billing™ uses two services for scheduled activities processing:
•The Duck Creek Scheduled Requests EXAMPLE Billing Components 0
•The DuckCreek_Async_Request_Queue_ EXAMPLE AsynceQueue 0
If scheduled activities do not work as expected, verify that the Duck Creek Scheduled Requests EXAMPLE
Billing Components 0 and the DuckCreek_Async_Request_Queue_ EXAMPLE AsynceQueue 0 services are
running.
To verify the services are running:
1.From the Start menu, click Control Panel .
2.Click Administrative Tools .
3.Click Services .
4.Locate and click Duck Creek Scheduled Requests EXAMPLE Billing Components O .
5.Do one of the following:
◦Click Start .
◦Click Restart .
6.Locate and click DuckCreek_Async_Request_Queue_EXAMPLE AsyncQueue 0 .
7.Repeat Step 5 .
Following are the steps involved in scheduled activities processing:
1.The Duck Creek Scheduled Requests EXAMPLE Billing Components 0 service queries for outstanding scheduled
activities in the DC_BIL_ScheduledActivities table.
2.Any outstanding activities are set to process, and a request to process the appropriate activities is sent to the
server.
3.The request is processed by the server, and asynchronous activity is scheduled if required.
4.Any scheduled asynchronous activity is sent to the Semaphore table.
90 Contains proprietary information. Copyright 2012 Accenture Duck Creek. All rights reserved.

5.The DuckCreek_Async_Request_Queue_EXAMPLE AsyncQueue 0 reads the Semaphore table and executes
the request.
6.After the request is completed, the scheduled activity item is set to a status of C (Complete) in the
DC_BIL_ScheduledActivities table.

Troubleshooting the MSMQ Billing Listener
The DuckCreek_MSMQBillingListener_EXAMPLE Billing Components 0 service logs the requests and responses for
errors to the BillingListenerErrors file.

The request and response files for Duck Creek Billing™ errors share the same unique name. For example, if a request
